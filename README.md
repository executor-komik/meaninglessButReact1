# Haven Hotel

Haven Hotel is a React and TypeScript client portal backed by a FastAPI service
and a local SQLite database. The application is being delivered in phases; this
branch currently implements Phase 1 (customer registration, role-specific sign
in, session persistence, and account dashboards).

“Haven Hotel” is a temporary working name until the client provides the hotel’s
brand.

## Run locally

Use Node.js 20.19 or newer in the 20.x line, or Node.js 22.12 or newer.
Python 3.10 or newer is required for the API.

On Windows, run:

```powershell
npm run hotel
```

The script creates `backend/.venv` if needed, installs the lightweight backend
requirements, starts the API on `127.0.0.1:8000`, and starts Vite. Open the URL
printed by Vite. The SQLite database is created at `backend/.data/hotel.db` and
is intentionally ignored by Git.

The frontend-only `npm run dev` command can be used for UI work, but account
registration and sign-in require the API. Use `npm run hotel` to run both.

## Provision an administrator

Admin registration is intentionally not public. After running `npm run hotel`
once to create the Python environment, open another PowerShell window and run
the command below for each admin account:

```powershell
Set-Location backend
.\.venv\Scripts\python.exe -m app.bootstrap_admin
```

The command prompts for an admin ID, display name, and password. The password
is entered without echo and must be 8–30 characters with uppercase, lowercase,
and a special character. There is no public admin signup or default password.

Customer IDs are generated at registration and shown on the success screen.
Passwords are stored as salted PBKDF2 hashes. Sign-in uses a server-managed,
HTTP-only session cookie; the session itself is persisted in SQLite. Set
`HOTEL_COOKIE_SECURE=true` when serving the API over HTTPS.

## Phase 1 scope and known limits

- Customer registration validates the provided name, email, country calling
  code, 10-digit mobile number, address, and password.
- Admins are provisioned by the operator. Customer and admin sign-in use
  separate role choices and server-side role checks.
- Customer and administrator dashboards are present. Reservation, billing,
  history, bookings, room status, and support navigation is visible but
  intentionally disabled until those phases are implemented.
- Registration acknowledgement displays the generated Customer ID. Email
  verification and account recovery are not part of this phase, so the customer
  must save that ID.
- This local SQLite setup is suitable for development, not yet for a public
  production deployment. Production needs managed storage, HTTPS, backups,
  operational account recovery, and deployment-specific secret/configuration
  handling.

## Provisional product defaults for later phases

These are working assumptions, not client-approved policy:

- Currency: INR.
- Room types and nightly rates: Standard ₹3,000, Deluxe ₹5,000, Suite ₹8,000.
  Treat these as illustrative room charges before any taxes or extras; tax and
  invoice treatment needs confirmation before release.
- Stay length: at least one night; dates are hotel-local calendar dates.
- Cancellation: free until 48 hours before check-in; cancellations inside that
  window and no-shows incur one night's room charge.
- Reservation requests remain pending until an administrator approves them.
- Customer ID is generated by the app. A 13-digit Payment Method ID is a
  separate identifier and must never be treated as a card number. The app will
  not store card numbers or CVV; any real payment integration must use a
  payment provider.
